# Systematic Debugging — 系统化调试方法论

为家航项目的高效调试流程，尤其针对 BLE 蓝牙定位、地图渲染、后端性能。

## 调试五步法

### Step 1: 复现 → 隔离
```
- 用最简步骤复现 bug
- 二分法隔离：是前端还是后端？是网络还是逻辑？
- 记录精确的复现条件（设备型号、OS 版本、操作步骤）
```

### Step 2: 假设 → 验证
```
- 列出 3 个最可能的原因，按概率排序
- 每个假设设计一个最小验证实验
- 用 console.log / 断点 / 抓包 快速验证
- 排除后更新假设列表
```

### Step 3: 定位 → 修复
```
- 确定根因后，先写失败的测试用例
- 最小化修复（≤ 5 行变更原则）
- 确保修复不引入新问题
```

### Step 4: 验证 → 回归
```
- 运行完整测试套件
- 在真机上验证（微信小程序必须真机测试）
- 检查相关功能有无回归
```

### Step 5: 沉淀 → 预防
```
- 记录根本原因和修复方案
- 如果是系统性缺陷，加 lint 规则或测试用例
- 更新 CLAUDE.md 的已知问题区
```

## BLE 蓝牙定位专项调试

### 常见问题 & 排查路径

```
问题：位置漂移
  → 减小 txPower？增加采样窗口？
  → 卡尔曼滤波参数是否合理？
  → 是否有金属货架反射信号？

问题：楼层识别错误
  → 气压计数据是否被使用？
  → 楼层间 beacon 信号是否有足够衰减？
  → 电梯/楼梯区域的过渡逻辑？

问题：延迟过高
  → BLE 扫描间隔是否太短？
  → 后端计算是否在本地做（边缘计算）？
  → WebSocket 推送是否做了节流？
```

## 工具速查

| 场景 | 工具 |
|------|------|
| 小程序调试 | 微信开发者工具 → 调试器 → AppData |
| 网络抓包 | 微信开发者工具 → Network |
| BLE 调试 | nRF Connect (手机端) |
| 后端断点 | VS Code Debugger (attach to Node) |
| 数据库慢查询 | `EXPLAIN ANALYZE` + pg_stat_statements |
| Redis 缓存 | `redis-cli MONITOR` |
| 性能分析 | Chrome Performance + Node.js --inspect |
