## 二、四端 + 一服务

### 2.1 端侧矩阵

| 端 | 项目 | 用户 | 载体 | 核心场景 | 进度 |
|---|------|------|------|---------|:---:|
| **C端** | `weijiahang-miniapp` | 业主/采购商 | 微信小程序 | 搜商品→AI推荐→导航到店→下单 | ✅ 80% |
| **P端** | `weijiahang-navigator` | 领航员 | 微信小程序 | 接单→带看→验货拍照→赚佣金 | 🚧 20% |

| **服务** | `weijiahang-server` | — | Nest.js | REST API · WebSocket · AI代理 | 🚧 15% |

```
  平台派单(就近) → 领航员接单 → 到市场等待客户
```

### 7.2 关键模块职责

| 模块 | 职责 | 关键技术点 |
|------|------|----------|
| **auth** | 微信登录 JWT 签发、多角色鉴权 | `@nestjs/jwt` + `passport-jwt` |

| **reviews** | 商户评价、领航员评价 | — |
| **ads** | 首页 Banner、商户推广位 | — |
| **admin** | 运营后台专用接口（审核、统计） | — |

### 7.3 BLE 室内定位数据流

```
BLE 信标 (iBeacon)                     手机小程序
    │                                      │
    │  广播 UUID + Major + Minor + TX      │
    │  ─────────────────────────────────→  │
    │                                      │ 监听 onBeaconUpdate
    │                                      │ RSSI 信号强度采集
    │                                      │
    │                              ┌───────┴───────┐
    │                              │  前端卡尔曼滤波  │
    │                              │  平滑RSSI波动   │
    │                              └───────┬───────┘
    │                                      │
    │                              ┌───────┴───────┐
    │                              │  三边定位算法    │
    │                              │  (3+信标交汇)   │
    │                              └───────┬───────┘
    │                                      │
    ▼                                      ▼
  Server:                                
  GET /navigation/map/:marketId/:floor   → 返回该楼层信标坐标网格
  POST /navigation/position               ← 上传当前位置(可选)
  GET /navigation/route?from=x,y&to=shopId → 返回最优路径
```

## 九、数据架构

### 9.1 核心实体关系

```
  markets (市场) 1───N floors (楼层)
    │                   │
    │                   └───N beacons (蓝牙信标)
    │
    └───N shops (店铺) 1───N products (商品)
              │
              │                    ┌── navigator (领航员)
              │                    │
              └──N orders (订单) ──┤
                                   │
                                   └── user (业主)
                                        │
                                        └──N favorites (收藏)
                                        └──N addresses (地址)
                                        └──N reviews (评价)
```

### 9.2 关键数据特性

| 实体 | 存储引擎 | 关键索引 |
|------|---------|---------|
| shops | PostgreSQL | `GIST(location)` PostGIS 空间索引 |
| markets | PostgreSQL | `GIST(boundary)` 多边形范围查询 |
| beacons | PostgreSQL | `(market_id, floor, major, minor)` 联合唯一 |
| orders | PostgreSQL + Redis | Redis 缓存热点订单状态 |
| 用户会话 | Redis | JWT token → user_id，TTL 7d |
| 领航员位置 | Redis | `GEOADD navigators:online` 实时位置集合 |

## 十一、架构决策记录

| 决策 | 理由 |
|------|------|
| **微信小程序优先** | C端用户 40+ 为主，零下载门槛；微信蓝牙 API 支持 BLE |
| **Nest.js 后端** | 模块化架构支持 5 端并行开发；装饰器风格清晰 |
| **PostgreSQL + PostGIS** | 建材市场是空间场景，"附近店铺"是核心查询 |
| **Redis 存领航员位置** | `GEOADD` 支持"找最近领航员"毫秒级查询 |
| **SQLite 开发 / PostgreSQL 生产** | 开发免安装零配置；生产用空间索引 |
| **自定义 TabBar** | 品牌 Logo + 回到顶部交互，微信原生 TabBar 不支持 |
| **CSS 图标全平台零 Emoji** | 40+ 用户手机系统 Emoji 显示不一致，CSS 图标可控 |
| **不碰资金池** | 建材单笔金额大，资金池监管风险高；走微信支付直接到商户 |
